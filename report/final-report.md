# 最终报告 — 个人网站规范化 AI 开发

## 一、项目定位

**目标用户**：面向互联网/金融行业实习招聘方（面试官 > HR > 同行校友）

**个人品牌**：管理科学与工程硕士在读 | 互联网商业化 | AI 工具应用探索

**核心传递**：愿意尝试新技术、紧跟时代发展、兼具金融与互联网复合背景

## 三、AI 协作过程

### Phase 1：需求定义
- **Brainstorm**：通过对话明确网站定位、目标用户、希望传递的印象
- **PRD**：定义项目目标、用户场景、内容板块、排除边界、完成标准、隐私边界
- **Design**：定义页面结构、配色方案、文件映射、响应式要求、素材来源
- **Checklist**：制定 22 项可验证检查标准，每项均有明确验证方式和预期结果

### Phase 2：迭代开发与验证
- **内容替换**：AI 基于用户提供的简历，将模板占位内容逐步替换为真实数据
  - 个人信息（姓名、职位、简介）
  - 实习经历（新浪微博 + 浦发银行）
  - 教育背景（深圳大学 管理科学与工程 硕士）
  - 项目经历（量化分析、市场调研、创协）
  - 技能清单（软件工具、语言能力、兴趣方向）
- **头像生成**：AI 绘制 SVG 插画风格小猫头像，替代真人照片
- **目录结构**：按作业要求搭建网站源文件与资源/、docs/、report/、screenshots/
- **README 重写**：替换原模板说明为项目专属介绍

### Phase 3：部署与验证
- **Git 提交**：通过浏览器上传方式完成首次提交
- **GitHub Pages 部署**：启用 Pages，从 master 分支构建
- **错误修复**：修复了 _config.yml 中的 YAML 语法错误（email 行合并）、版本不一致导致的重复标题行
- **语言统一**：根据用户反馈，将板块标题统一为中文

## 六、遇到的问题与反思

### 问题 1：YAML 语法错误
**现象**：Pages 构建失败，报错 "mapping values are not allowed in this context at line 11"
**原因**：PowerShell 替换操作导致 email 行与注释合并为一行
**解决**：删除 _config.yml 后使用 apply_patch 重写，确保 YAML 格式正确

### 问题 2：重复标题导致构建失败
**现象**：Pages 构建报错 "Could not locate the included file .section-..html"
**原因**：YAML 中同时存在英文标题（Experience/Education/Projects）和中文标题（实习经历/教育背景/项目经历），前者缺少 layout 字段
**解决**：在 GitHub 编辑器中删除多余的英文标题行

### 问题 3：代理网络无法推送
**现象**：沙箱环境和本地终端均无法通过 git push 推送代码
**原因**：代理软件未运行，HTTPS 和 SSH 均被阻断
**解决**：通过 GitHub 网页端拖拽上传 + 在线编辑完成文件更新

### 反思
- 配置驱动模板（如 Modern Resume Theme）大幅降低了手动编码工作量，所有内容修改集中在 _config.yml 一处
- 文件编码一致性需要特别留意——PowerShell、Python、GitHub 编辑器之间的编码转换容易引入 BOM 或损坏
- YAML 对缩进和格式敏感，手动替换时需保持结构完整
- 网络环境问题影响了 git 工作流，浏览器上传作为备用方案可行但效率较低
